# AGENTS.md

## Ignore misleading docs
- `README.md` is still the default Astro starter README. Do not treat it as project-specific guidance.

## Repo shape
- This is a single-package Astro 5 site, not a monorepo.
- Main page entrypoints live in `src/pages/`; the shared shell is `src/layouts/Layout.astro`.
- The coverage detail pages are generated by `src/pages/cobertura/[zona].astro` from markdown files in `src/content/*.md`.

## Content wiring to keep in sync
- Adding or renaming a coverage city requires updating all three places: `src/content/<zona>.md`, the `ciudades` array in `src/pages/cobertura/[zona].astro`, and the dropdown links in `src/components/navBar.astro`.
- `getStaticPaths()` only lists `playa-del-carmen`, `tulum`, and `puerto-morelos`; extra markdown files alone will not create routes.

## Styling and frontend conventions
- Tailwind CSS v4 is enabled through the Vite plugin in `astro.config.mjs`; there is no `tailwind.config.*` file.
- Global theme tokens, fonts, and Swiper overrides live in `src/styles/global.css`.
- Client behavior is plain inline `<script>` blocks inside `.astro` components plus direct `swiper` imports; there are no framework islands.

## Commands
- Install dependencies first: `npm install`
- Dev server: `npm run dev`
- Production build: `npm run build`
- Astro type/content check: `npm run astro -- check`
- There are no repo-defined lint or test scripts right now.

## Deployment constraints
- Production image build is defined in `dockerfile.prod`: build Astro with Node 22 Alpine, then serve `dist/` from Nginx.
- Nginx listens on port `8080` (`nginx/nginx.conf`), and the Kubernetes manifest and GitHub Actions deploy flow expect that port.
- CI in `.github/workflows/workflow.yml` builds and pushes `dockerfile.prod` to DigitalOcean Container Registry, then updates the `website` deployment in namespace `enlaces`.
